# ToDo — Projects + task delete review

Saved: 2026-08-11 17:23:13

Scope: projects feature, task assignment, project detail list, trash-row delete, and AlertDialog confirm.

---

## Errors / bugs

### P0

1. **Deleting a parent does not cascade to children**  
   `confirmDeleteTask` deletes one row. Subtasks keep `parent_id` pointing at a missing parent. They can still show as “roots” via the orphan filter, or break elsewhere. Prefer cascade delete in DB, or delete children in the same action.

2. **Schema drift still present (pre-existing, still bites this feature)**  
   UI uses `parent_id`, `position`, `ai_generated`, status `todo|done`. Checked-in migrations only had basic task columns + later `project_id`. If live DB and migrations diverge, inserts/filters fail intermittently. Types still omit `parent_id` / `position` / `ai_generated`.

3. **Task status CHECK mismatch risk**  
   Project create/toggle uses `"todo"` / `"done"`. Original migration allowed `pending|in_progress|completed`. If that CHECK still exists in production, creates/toggles error.

### P1

4. **`ProjectDetail` can hang on “Loading project...”**  
   `loading` only clears in `fetchTasks().finally`. If `fetchProject` fails/navigates away first, or `projectId` is missing, you can get a stuck or odd loading state. Clear loading in both paths; set loading false when `!projectId`.

5. **Sidebar delete + row delete race with open sheet**  
   Opening AlertDialog while `TaskDetailsSidebar` is open stacks two overlays. Usually OK, but focus/scroll can feel off. Consider closing the sheet when `requestDeleteTask` runs from the sidebar.

6. **Unverified update success on delete**  
   Delete does not `.select()` / check row count. RLS “0 rows deleted” can look like success. Same class of bug fixed on task save.

## Medium issues

### P2

7. **Nested subtasks don’t expand**  
   `TaskRow` children don’t get `subtasks` / `isExpanded` / `onToggleExpand`, so only one level expands. Fine for MVP, wrong if hierarchy is deeper.

8. **Hover-only trash is weak on touch**  
   `opacity-0 group-hover:opacity-100` hides delete on mobile. Use always-visible on coarse pointers, or a overflow menu.

9. **Duplicated project status/color maps**  
   `STATUS_LABELS` / `STATUS_STYLES` copy-pasted in `Projects.tsx` and `ProjectDetail.tsx`. Extract shared constants/types.

10. **`Projects` task counts are N+1-ish and unbounded**  
    Loads all `project_id`s for counting. Prefer a single grouped count query/view, or embed `tasks(count)` if Supabase relationship is set up.

11. **No edit/archive/delete project UI**  
    Can create projects, not manage them from the list (except via DB).

12. **Hard delete vs “remove from project”**  
    Trash permanently deletes. Label/dialog is clear enough; an alternate “Remove from project” (`project_id = null`) may match user mental model better for project context.

## Smaller / polish

### P3

13. **`error: any`** widely used — match `Tasks.tsx` `unknown` + `logError` if lint consistency matters.
14. **Smart quotes** in dialog copy (`“${title}”`) — fine in UI, slightly annoying in some fonts/encodings.
15. **AlertDialogAction + `preventDefault`** — correct for async delete; good.
16. **Unused imports** in `TaskDetailsSidebar` (`SheetHeader`, `SheetTitle`, `SheetDescription`, `X`) — pre-existing noise.
17. **Client env key naming** — `client.ts` uses `VITE_SUPABASE_ANON_KEY`; `.env` also has publishable key. Works if both set; easy to misconfigure.
18. **Migration not applied = silent feature break** — ensure `20260810120000_create_projects.sql` is applied on every environment.

## What looks solid

- Optional `onDelete` on `TaskRow` keeps `/tasks` clean.
- `stopPropagation` on trash avoids opening the drawer.
- AlertDialog matches Calendar destructive pattern and taste (no `confirm()`).
- Orphan root filter (`!parent_id || parent not in project`) is the right fix for assigned children.
- Save path verifies update with `.select().maybeSingle()`.
- RLS on `projects` mirrors tasks; `ON DELETE SET NULL` on `project_id` is a safe default.
